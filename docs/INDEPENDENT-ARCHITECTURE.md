# Independent AgentLand architecture

The macOS menu-bar companion manages a Go host and opens a terminal-first local web workspace. The iPhone/iPad app owns its SwiftUI workspace and talks to the host's `/v1` API. The repository holds only AgentLand's own code, its PixelLab art and pinned third-party packages; the copied CPTR/Computer reference was removed from the tree and git history on 2026-09-23.

The local web architecture and launch/authentication boundary are recorded in
[LOCAL-WEB-WORKSPACE.md](LOCAL-WEB-WORKSPACE.md). That document supersedes the
earlier native Mac workspace presentation described below; persistence and
server ownership guarantees remain in force.

## Responsibilities

| Component | Owns | Does not own |
|---|---|---|
| iOS AppModel / workspace | Saved hosts, selected project, tabs, local drafts, app lock | Desktop process lifetime |
| AgentLandCore | Validated HTTPS origins, transport, API models, revision and persistence contracts | Browser-delivered UI |
| macOS companion | Menu-bar lifecycle, independent setup/settings/pairing windows, authenticated browser launcher; certificates, owned Go host and bundled OpenCode runtime, Keychain service/provider secrets | VPN, relay, Tailscale configuration, model billing or mobile credentials |
| Go host | Authentication, project authorization, files, device state, adapter, bounded terminal replay and loopback web gateway/state | Model billing, mobile tab restoration |
| Bundled managed OpenCode | Agent sessions, tool interactions and PTY terminals in isolated per-app XDG storage | AgentLand device authentication or provider billing |

The Go host and protocol client carry forward the owner's independently developed archived backend/protocol work. New native product views replace the rejected prototype UI. Provenance is recorded in component READMEs. SwiftTerm is fetched directly at a pinned upstream revision; the app includes its license.

## Connections and trust

Direct HTTPS is the baseline. A publicly trusted host certificate uses normal platform validation. A private host certificate requires an explicitly entered SHA-256 fingerprint; the mobile transport matches the certificate and retains hostname/validity checks. Tests reject an untrusted certificate, wrong fingerprint and wrong hostname before exercising successful pairing.

An existing Tailscale network can carry the same HTTPS traffic. The app does not open Tailscale, change VPN settings or show a connection prompt on an ordinary paired launch. Bonjour discovers running HTTPS hosts on the local network from the pairing screen. Remote access over iroh (off by default; docs/HOST-API.md "Remote access (iroh)") lets paired devices reach the Mac peer to peer: the Mac app maps one UDP port on the router itself, admits only paired devices' node IDs and bridges their streams to the host's tunnel socket, with the same pinned HTTPS inside; n0's public relays are only an opt-in fallback, and the Mac's changed address reaches devices through the owner's own iCloud. The Mac's side is in `macos/README.md`, "Remote access". There is no owned internet relay or AgentLand cloud directory. A private certificate establishes host identity after out-of-band comparison; it does not establish reachability.

Pairing codes expire and can be used once. Device credentials are hashed in the host state and placed in AgentLand's Keychain namespace on iOS. Redirects are declined. Origins, bearer authorization, project selection, sizes and request formats are checked at the API boundary. Revocation rejects subsequent device requests.

Desktop PINs contain ten cryptographically random decimal digits. The host permits at most ten pairing attempts per client address and thirty across all addresses per minute. PINs expire within ten minutes; ordinary CLI high-entropy pairing codes remain compatible. The Bonjour TXT record contains only protocol version, HTTPS origin and certificate fingerprint. Mobile treats those records as untrusted: PIN pairing requires explicit comparison with the desktop's complete fingerprint. Scanning the desktop QR code carries the fingerprint and single-use code out of band, followed by an explicit Pair action. QR parsing rejects wrong versions, expired invitations, oversized input, non-HTTPS addresses, credentials and extraneous URL fields.

The desktop captures the actual listener, advertised hostname and certificate when starting its child host. Apple certificate policy validates the hostname and validity, and a pinned HTTPS health check must succeed before it advertises. Editing Settings cannot silently change the advertised identity of a running host. Stop, quit and process death withdraw discovery and clear the displayed pairing invitation. The menu-bar app keeps ownership when its windows close; Quit still stops its owned Go host and managed OpenCode runtime.

The default Mac flow starts the bundled, pinned OpenCode runtime on loopback with isolated XDG config/data/cache/state under Application Support. A fresh cryptographically random service password belongs to each managed service lifetime; it stays in the controller's memory and is passed only to its two owned children. It is discarded after both stop. Provider keys persist in Keychain; no model credential is sent through the mobile protocol. Provider/model selection writes the managed runtime configuration but does not validate paid access by saving a key. Advanced Settings can instead use an existing loopback OpenCode service and its existing Keychain password; that legacy credential is preserved separately.

The Mac self-readiness check connects to loopback for its known wildcard listener while validating the advertised certificate hostname, validity, and exact fingerprint. It therefore does not depend on its own Bonjour hostname resolving before local-network consent. Mobile connections still use the advertised HTTPS address and normal paired transport. Bonjour publication and mobile reachability are verified separately from local child readiness.

The Mac workspace uses the same HTTPS API with a separate random token held only for the owned host process lifetime. The Go host accepts it only from a loopback peer, gives its terminal operations a local owner ID, and never writes it as a paired device. The client connects to 127.0.0.1, pins the certificate fingerprint, and evaluates certificate validity against the advertised hostname. This keeps the Mac's own workspace independent of paired mobile credentials. The production Mac window opens directly to Home and also owns Pairing, Devices, and Settings navigation; changing pages does not stop the host.

Mobile clients report foreground presence with an authenticated 15-second heartbeat and clear it on backgrounding. The host expires presence after 45 seconds and excludes revoked devices. Authorization remains based on the paired token, not on presence. The Mac companion refreshes its device list while connected so its native menu can show current device use before the menu opens.

Reachability is separate from presence. While in the foreground, the mobile app keeps one authenticated pulse stream open (`GET /v1/pulse`: a line every 1.5 s, renewed every 24 s). A graceful host shutdown first sends `stopping` on every pulse and releases terminal long-polls, then drains HTTP; the app shows that the Mac app stopped within about a second. A process that dies closes its sockets, which the app sees at once. A Mac that sleeps or leaves the network sends nothing; the app reports it unreachable when the stream is silent for 4.5 s. A lost network path is reported immediately from the system path monitor. While offline the workspace shows a banner, surfaces keep their content and pause polling, and terminal typing is refused with a visible notice rather than queued. Reconnection retries with a short backoff (0.5–2 s) and immediately after a network change or Retry; recovery increments a connection epoch so surfaces resume from their terminal cursors and reload only failed content. Hosts without the pulse route fall back to a 3-second health check.

## Workspace and recovery

Tabs and the selected tab are typed local state scoped to host/device identity. The root Home and additional Home tabs share one launcher layout; the New Home Tab keyboard/menu command (⌘T) creates a separate Home tab, and a Home tab's action turns that tab into the opened workspace tab in place (the root Home stays). No workspace is assumed from the host's project list: the current workspace is only what this device opened or selected, remembered per host/device identity, and Home actions without one open the workspace picker first. The shared full-width shell uses a top-center picker for Home, folders and their retained tabs, with standalone chats in a separate group. Current-tab actions and Close Tab live in a trailing menu. Home is a fixed safe-area launcher at ordinary text sizes, with accessibility scrolling when needed. Its menus provide standalone/agent chats, Files, Git, Browser, searchable history and archives. Settings opens upward from Home in a tinted modal drawer on iPhone, iPad and Mac; the Mac native command returns Home before opening it. Array-only saves migrate without dropping tabs or drafts. Dirty editor closes require an explicit choice; disk persistence remains debounced while in-memory edits immediately protect the close path. Explicit close persists immediately, on both phone and tablet. Discovering a still-running remote session does not reopen it. Retained tab bodies preserve terminal rendering/cursor state; inactive tabs relinquish input and accessibility. App lock overlays those views. Polling pauses while locked, inactive or backgrounded.

Mutations have explicit uncertain-delivery outcomes. A transport failure after sending a prompt or terminal operation is not permission to resend. Terminal input is UTF-8 chunked, queued with resize operations, and bounded; keys typed during an in-flight request are sent together in order. Uncertain delivery blocks further input until the user explicitly chooses Resume typing; a request that provably never reached the host (refused connection, no route, failed TLS) is reported as not sent and does not block. Terminal output is a host long-poll, so echo arrives as soon as the PTY writes. Named terminal actions are a fixed server-side allowlist: shell, bundled/installed OpenCode, and installed Claude Code or Codex. Capabilities expose only available programs; clients cannot supply executable paths, arguments or environment. OpenCode attaches to the same local agent service with credentials in child environment variables. Terminal replay is bounded and process-local. Reconnection does not promise a full screen snapshot or survival across host restarts.

Chat model and status endpoints retain bearer authentication and project/session authorization. The provider catalog exposes only connected-model display metadata. Optional model/agent fields preserve the original prompt contract, while Build/Plan selection does not override tool permissions.

Files are confined to configured roots with `os.Root`, including parent handles for writes. Only bounded regular UTF-8 text is editable. Unix file checks open nonblocking so a FIFO cannot stall a request. Saves require the content revision, write/sync a temporary file and rename it. AgentLand writes are serialized; an external editor can still race between the last revision check and rename because it does not participate in that mutex. Draft persistence records the original base revision so relaunch cannot bypass conflicts.

The macOS companion stores non-secret preferences, including whether a connection is desired, and preserves additional configured projects during edits. View lifetime does not own service lifetime: closing a window leaves a desired connection running, Disconnect clears that intent, and Quit stops both owned processes with bounded cleanup. A later launch resumes only a desired connection. Commands drain output incrementally with bounded capture and timeouts. The host state preserves paired devices and pending codes when configuration changes. Login at launch uses optional `SMAppService.mainApp` registration only after a user enables it; it is never registered by setup.

## Development and evidence

The test commands are in the [README](../README.md#verify). Production Swift-to-Go TLS, file conflicts, credential revocation, real installed OpenCode compatibility, and simulator UI paths have separate checks. Tests use disposable state and stop only processes they created. They do not modify other installed apps, their backends or Tailscale.

The intended business model remains a one-time mobile purchase and free user-hosted companion; model usage is external. That is a product direction, not an implemented storefront, lifetime service commitment or release approval. macOS packaging is local development packaging; Windows/Linux builds currently cover the CLI only. Public distribution requirements remain explicitly tracked rather than implied by the migration.
