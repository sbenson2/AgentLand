## Platform, provider and state tradeoffs

- Paseo’s README advertises iOS, Android, desktop, web and CLI; that is backed at least structurally by an Expo app, Electron app, CLI and daemon packages. [package map](https://github.com/getpaseo/paseo/blob/f232d23e9a7b1ab4fdeaf198f2aabd8df8fb34ed/README.md#L166-L175) AgentLand’s shipping UI code is native iPhone/iPad/macOS. This makes Android/web/Electron/headless SDK access a real product reach gap for AgentLand, while Apple-native SwiftUI and the Mac companion are a deliberate implementation differentiation, not a comparative quality claim.
- Paseo has first-party provider clients and static visible mode definitions for Claude, Codex, Copilot, OpenCode, Pi and OMP, with more adapters registered internally. [manifest](https://github.com/getpaseo/paseo/blob/f232d23e9a7b1ab4fdeaf198f2aabd8df8fb34ed/packages/protocol/src/provider-manifest.ts), [registry](https://github.com/getpaseo/paseo/blob/f232d23e9a7b1ab4fdeaf198f2aabd8df8fb34ed/packages/server/src/server/agent/provider-registry.ts) AgentLand has three named adapters plus an open-ended installed ACP-agent catalog, with runtime-reported session modes; [provider catalog](../shared/AgentLandCore/Sources/AgentLandCore/ProgramCatalog.swift), [ACP modes](../desktop/acp_engine.go). Paseo has more named adapter integrations and a separate plugin extension point. This does not establish that AgentLand supports fewer usable agents: its ACP registry is extensible, and Paseo’s inspected mode manifest itself has a TODO to replace static modes with runtime discovery. AgentLand does have a specific limitation: scheduling currently accepts only its three native adapters, not arbitrary ACP agents.
- Both persist agent/workspace state. Paseo’s storage retains provider session handles, cwd/workspace/configuration and archival fields atomically. [agent storage](https://github.com/getpaseo/paseo/blob/f232d23e9a7b1ab4fdeaf198f2aabd8df8fb34ed/packages/server/src/server/agent/agent-storage.ts) AgentLand separately owns local device tabs/drafts and preserves inactive terminal/editor state. [architecture](../docs/INDEPENDENT-ARCHITECTURE.md#L41) These are different recovery and ownership choices; source review alone cannot establish which is more robust.

## Remote access and security framing

Both products are self-hosted and provide encrypted/direct remote paths. Paseo’s README says its relay is opt-in and end-to-end encrypted; source also has daemon bearer auth and operation permissions. [README connectivity](https://github.com/getpaseo/paseo/blob/f232d23e9a7b1ab4fdeaf198f2aabd8df8fb34ed/README.md#L78-L108), [auth](https://github.com/getpaseo/paseo/blob/f232d23e9a7b1ab4fdeaf198f2aabd8df8fb34ed/packages/server/src/server/auth.ts), [operation permissions](https://github.com/getpaseo/paseo/blob/f232d23e9a7b1ab4fdeaf198f2aabd8df8fb34ed/packages/server/src/server/authorization/operation-permissions.ts).

AgentLand’s concrete distinction is its Apple/device pairing model: QR or single-use PIN plus full certificate-fingerprint comparison, device-scoped credentials, and optional paired-node iroh transport that continues pinned HTTPS. [architecture trust model](../docs/INDEPENDENT-ARCHITECTURE.md#L17) Paseo’s explicit plugin model, by design, lets trusted plugin code access its daemon machine and connected clients. [plugin runtime](https://github.com/getpaseo/paseo/blob/f232d23e9a7b1ab4fdeaf198f2aabd8df8fb34ed/packages/server/src/server/plugins/runtime.ts) These are different extensibility/trust boundaries; no security-superiority claim is warranted without threat-model and runtime audit work.

## Workflow options within AgentLand's UI focus

The owner's stated direction is the native UI and polish. The current Home, navigation and Settings work follows that direction; the source comparison does not establish a comparative usability ranking. Similar core features can serve different priorities.

If workflow expansion becomes useful, my inference from the reviewed product paths is to start with **managed Git worktrees and branch operations**, then **forge/PR status and actions**. They complete the existing coding workspace without requiring a new client stack. **Scheduling arbitrary ACP agents** and **two-way voice** are further options if they match actual use. A trusted-plugin API and Android/web clients are larger product decisions; they bring reach and extensibility but also add lifecycle, permissions and platform work. None is part of this redesign's implementation scope.

Keep the Apple-native interface and standalone chat with reviewable memory as deliberate product strengths. Generic self-hosting, encrypted remote access, files, terminals, schedules and dictation already overlap with Paseo and should not be presented as exclusive features.
