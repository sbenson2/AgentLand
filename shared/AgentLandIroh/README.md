# AgentLandIroh

iroh's Swift bindings as AgentLand builds them (iOS 26, macOS 26), for reaching the
owner's Mac from anywhere through iroh (docs/HOST-API.md "Remote access (iroh)"): the Mac
maps one UDP port itself and runs no relay; n0's public relays are an opt-in fallback. The
Mac app links it (`macos/Package.swift`: `IrohMacEndpoint`, `MacTunnelBridge`,
`RemoteAccessService`), and the iPhone and iPad app through `shared/AgentLandRemoteAccess` (the
phone's endpoint and bridge). The crates' notices are `third_party/iroh-ffi/crate-licenses.txt`
(the Mac bundle) and `ios/AgentLand/IrohLib-NOTICES.txt` (the phone), one text written by
`scripts/collect-iroh-ffi-notices.py`. Remote access ships off by default behind one switch on
the Mac.

- `IrohFFI`: `Frameworks/IrohLib.xcframework`, static libraries for iOS arm64, the iOS
  simulator (arm64) and macOS arm64 with the FFI's C header. Built from pinned source by
  `scripts/build-iroh-ffi.sh`; not committed. The manifest stops with a message when it is
  missing. Source, patches, versions and licenses: `third_party/iroh-ffi/README.md`.
- `IrohLib`: the Swift wrapper uniffi generates (`Sources/IrohLib/IrohLib.swift`, committed,
  regenerated by the script; Swift 5 language mode, as generated). Before it compiles, the
  `VerifyIrohLib` build tool plugin checks every file of the xcframework against the committed
  `third_party/iroh-ffi/IrohLib.sha256` (`scripts/verify-iroh-ffi.sh`); a library the record
  does not list fails the build before anything links it. This runs in SwiftPM and in Xcode,
  again whenever the framework, the record or the script changes.
- `AgentLandIroh`: re-exports `IrohLib` and adds `IrohPeerGate`.

## What the library cannot do

- **Map router ports.** iroh is compiled without its port mapper (no UPnP, PCP or NAT-PMP code
  in the library), and iroh-services, whose diagnostics probe the router, is not built. There is
  no option to turn it on. AgentLand makes and removes its own mappings and advertises them
  with `externalAddrs` or `addExternalAddr(addr:)`.
- **Use n0 by accident.** Options left unset mean `presetMinimal()`: no relays, no address
  lookup, nothing published to n0's DNS. n0's relays are used only when a relay mode names
  them (or `presetN0()` is passed).
- **Panic in `EndpointBuilder`.** A refused `bindAddr`/`bindPort` leaves the builder as it was;
  after `bind()`, calls that can throw fail and the others do nothing.

## An endpoint

The Mac's endpoint (`IrohMacEndpoint` in `macos/`):

```swift
let endpoint = try await Endpoint.bind(options: EndpointOptions(
    preset: presetMinimal(),                     // also the default: no n0 relays, DNS or pkarr
    secretKey: keyFromKeychain,                  // 32 bytes, this device only
    alpns: [Data("agentland/tunnel/1".utf8)],
    relayMode: RelayMode.disabled(),             // or the fallback's one n0 relay: customFromUrls([url])
    bindPort: 38842                              // the UDP port AgentLand maps itself
))
try await endpoint.addExternalAddr(addr: mappedAddress)  // the router mapping's global address
```

The relay TLS options (`relayTlsRoots`: `.custom` for a private CA or a self-signed relay,
`.embeddedPlus` to add one to the Mozilla roots) were built for a relay on the Mac, which the
owner's final design does not have; n0's relays use the default Mozilla roots. iroh applies one
TLS setting to every relay of an endpoint.

`setLogLevel` may be called any number of times; `watchAddr`, `watchHomeRelay` and
`watchNetworkChange` may be called from any thread. FFI calls cannot be cancelled from Swift
(`online()` has no timeout); race them against a timer instead of relying on task cancellation.

## The peer gate

iroh completes a handshake with any key, so the Mac hands a connection to AgentLand only
through `IrohPeerGate`:

```swift
let gate = IrohPeerGate(endpoint: endpoint)  // no list yet: every connection gets 503
let task = Task {
    for await connection in gate.connections(onRefused: { id in log(id) }) {
        serve(connection)
    }
}
gate.setAllowed(pairedEndpointIDs)     // the first list, then every change; no second gate
task.cancel()                          // stop reading; the next connection is refused
try await endpoint.close()             // stop accepting at once
```

`IrohPeerGate(endpoint:allowed:)` starts with a list instead.

- Each incoming connection first proves its source address with a QUIC retry, so a packet from
  a spoofed address never starts a handshake.
- Handshakes in progress are limited per source, `maxPendingHandshakesPerSource` (default 2). A
  source is an IPv4 address, a global unicast IPv6 /64 (2000::/3), any other IPv6 address on its
  own, or the sender a relay names (the endpoint ID the relay authenticated). Direct connections
  also share `maxPendingHandshakes` slots (default 64). Relayed connections from senders that are
  not listed (every relayed sender while the gate has no list) share
  `maxPendingUnlistedRelayedHandshakes` slots of their own (default 8), so a relayed stranger is
  refused with the gate's code like a direct one; relayed connections from listed senders use
  neither. Above a limit a new connection is refused before its handshake (a QUIC refusal without
  an application code, which the peer sees as a dial that fails). Handshakes run concurrently.
- Only a global /64 is one host's network. Other IPv6 addresses share their /64 with other hosts,
  so each counts on its own: unique local addresses (fc00::/7; Tailscale puts every node of a
  tailnet in one /64 of fd7a:115c:a1e0::/48, ZeroTier every node of a network), link-local ones
  and NAT64 ones (64:ff9b::/96, one IPv4 host each). Unique local and link-local addresses are
  not routed on the internet, and the retry makes a peer prove it receives at its address, so
  only a host on the Mac's own network or overlay can use them. A Teredo address (2001::/32)
  counts as the client IPv4 address it carries, since the clients of one Teredo server share a
  /64.
- A handshake that has not completed within `handshakeTimeout` (default 5 s) is dropped in iroh
  (`Accepting.connectWithTimeout`, patch 0006), which frees its slots. Without it a peer could
  hold a handshake open as long as it kept sending packets, since each one restarts QUIC's idle
  timers, and Swift cannot cancel the FFI call.
- So an internet host at one address holds at most 2 slots, each for at most 5 s, and cannot
  fill the shared slots or lock paired devices out.
- What is left:
  - Hosts at 32 or more sources that keep starting handshakes and never finish them can keep the
    shared slots full: many IPv4 addresses, many global IPv6 /64s (one /56 or /48 network has
    them), or one host on the Mac's own network or overlay that holds many unique local or
    link-local addresses. While they do, paired devices are refused on direct paths but still
    get in through a relay (dial the relay URL without direct addresses).
  - Devices behind one source share its 2 slots: one public IPv4 address (a network behind NAT,
    carrier-grade NAT) or one global /64. A device that shares a source with a stalling host may
    be refused on its direct path, and when more than 2 devices of one source handshake at the
    same moment, the others are refused and must dial again.
  - Anyone can make keys, so peers that keep starting relayed handshakes under new ones can keep
    the 8 unlisted relayed slots full. While they do, a device that is no longer listed and dials
    through the relay is refused before its handshake and learns that it is not admitted only at a
    later dial. Listed senders are not affected.
- A connection whose `remoteId()` is not listed is closed with code 403 (reason `not paired`)
  before any stream is read, on a direct path or through a relay; `onRefused` gets its ID.
- A gate without a list (`IrohPeerGate(endpoint:)`, until the first `setAllowed`) cannot tell a
  paired device from another, so it closes every connection it completes with 503 (reason
  `no peer list yet`), which asks the peer to come back, and calls no `onRefused`. `allowed` is
  nil until then.
- An allowed connection is handed to the current stream. When nobody reads (the reading task
  was cancelled or the stream released), the gate refuses the next connection and stops its
  loop; a new `connections()` call starts it again. A second call replaces the first stream.
- `acceptNext()` cannot be cancelled through the FFI, so use one gate per endpoint. A second
  gate on the same endpoint works, but the first gate's waiting loop takes (and refuses) one
  more connection before it stops.
- Revoking a device does not close connections already handed over; the reader does that.

## Building

```sh
scripts/build-iroh-ffi.sh
```

On the M1 mac mini: 770 s for the first build (crates already downloaded; each slice about
3–4.5 min of fat LTO, then 1 min 46 s for uniffi-bindgen), 445 s for a rebuild that recompiles
only the patched crate, 509 s for the rebuild that dropped the port mapper and iroh-services.
Builds on the same toolchain are byte-identical, which is what the record relies on; after a
deliberate change, `--update-record` writes a new `third_party/iroh-ffi/IrohLib.sha256` to
commit with it and lists the files that changed. The toolchain is pinned: Rust 1.94.1 and Xcode
26.6 (17F113), whose clang version the libraries embed. With another Xcode selected
(`xcode-select`, `DEVELOPER_DIR`) the script stops before building, and says which Xcode it
needs; `--check-xcode` runs only that check. C is compiled with that Xcode's clang and SDKs
whatever `cc` is on PATH, its install path is not embedded (and may contain spaces, as in
`/Applications/Xcode 26.6.app`), and the xcframework's `Info.plist` lists the libraries in a fixed
order. Every checkout shares the work directory; a run holds a lock on it for its whole length,
so a second run waits.

It uses Rust 1.94.1 from `~/.rustup` (no need to be on PATH) and adds the iOS targets if they
are missing, checked against the toolchain's own manifest. cargo-make is not needed. It also
fetches the iroh-relay 1.2.0 release binary (SHA-256 pinned) into `Frameworks/` for the tests;
`--skip-relay` leaves it out. `Frameworks/IrohLib.build.txt` records the commit, patch,
toolchain, patched-source and output SHA-256s.

Sizes: each static library is about 20.4 MB (iOS 20.4 MB, simulator 20.3 MB, macOS 20.5 MB;
24.8–24.9 MB with the port mapper and iroh-services). With those still in, a release arm64
executable that binds an endpoint, uses a relay map, TLS roots, streams and the peer gate grew
by 11.6 MB on iOS and 11.7 MB on macOS after `strip -x`; it was not measured again.

## Tests

Run them under the profile that refuses the router's port-mapping ports:

```sh
cd shared/AgentLandIroh
swift build --build-tests
sandbox-exec -f Tests/router-ports-denied.sb xcrun xctest .build/debug/AgentLandIrohPackageTests.xctest
```

(`swift test` itself cannot run under the profile: SwiftPM sandboxes its manifest build and
macOS refuses a sandbox inside a sandbox.)

The relay tests need `Frameworks/iroh-relay` (or `AGENTLAND_IROH_RELAY`). Without it they
fail, so a run that lacks the relay cannot pass unnoticed; `AGENTLAND_IROH_ALLOW_MISSING_RELAY=1`
makes them skip instead, with a warning on stderr and in the test summary.

All traffic stays on loopback: relays are the iroh-relay binary on 127.0.0.1 with throwaway
certificates made by `/usr/bin/openssl`.

- `EndpointTests`: connect, accept and streams both ways (1 MiB echo, SHA-256 checked); fixed
  bind port (a second endpoint on it fails; port 0 and `bindAddr` with `bindPort` are refused);
  external addresses advertised and removed; `watchAddr` (twice), `watchHomeRelay` and
  `watchNetworkChange` from Swift report changes and do not abort; `setLogLevel` four times;
  `presetMinimal` and options left unset have no relay; a refused `bindPort` after `bindAddr`,
  and every builder call after `bind()`, neither panic nor lose the builder.
  `IrohPeerGate`: a stranger is refused (403, no stream) and served once `setAllowed` lists it;
  after the reading task is cancelled the next dial is refused, a new stream from the same gate
  serves every dial, and a second gate on the endpoint serves all but at most one (refused, none
  left open). Handshakes are stalled through a UDP proxy that drops the server's replies after
  its retry: with `maxPendingHandshakes: 1` and one stalled, the next dial is refused within
  5 s; with two stalled from 127.0.0.1, a third dial from 127.0.0.1 is refused within 5 s and a
  dial from ::1 is served; once the proxy stops, a 1 s `handshakeTimeout` frees the slot within
  2.5 s and the next dial is served, while a 60 s one still holds it after 3 s. Over a relay a
  gate without a list closes a paired device's connection with 503 (no `onRefused`); with its
  list it serves the device, closes a relayed stranger's connection with 403 after its handshake
  (`onRefused` gets its ID), and serves a second paired device through the relay while a stalled
  direct handshake holds the only shared slot. A gate without a list closes a direct connection
  with 503 twice, an empty list with 403, and a list with the device serves it.
  `HandshakeSourceTests`: IPv4 addresses whatever the port, IPv4-mapped IPv6 as IPv4, global
  IPv6 by /64; Tailscale (both address layouts), ZeroTier, link-local and NAT64
  IPv6 by address; Teredo as the client's IPv4 address (RFC 4380's example); relayed senders by
  endpoint ID, in the listed or unlisted relayed pool by the list. `HandshakeSlotsTests`: relayed
  senders that are not listed fill only their own slots (a new key does not get past them, and
  direct handshakes and listed relayed senders still get theirs), and one of them holds at most
  its 2 per-source slots.
- `RelayTLSTests`: a relay with a certificate from a private CA is used only with that CA
  pinned (not with iroh's default roots, the embedded roots, another CA or an unrelated
  self-signed certificate), and with `.embeddedPlus` of that CA but not of another CA; a
  self-signed relay only with its own certificate pinned. Each refusal is seen twice: the relay
  logs the client's "unknown CA" alert, and the endpoint has no home relay after 6 s (a trusted
  one has it after about 3 s). A trusted relay carries a connection dialed by endpoint ID and
  relay URL alone, with no alert. An empty or unparsable pin fails the bind. (That the Mozilla
  roots still work under `.embeddedPlus` is the Rust test `test_relay_tls_roots_trust`.)
- `PortMapperTests`: `IrohSendRecorder` (test-only C target) records every `connect`,
  `sendto`, `send` and `sendmsg` the test bundle, and so the linked iroh library, makes to
  watched ports, before the system sees it. An endpoint whose options leave everything unset
  sends nothing to UDP 1900, 5350 or 5351 while it binds and runs 3 s (its relay client's
  `connect` to a silent listener is recorded, so the recorder sees iroh's calls), nor while it
  reaches a real relay, gets online and runs 3 s more.
- `IrohLibRecordTests`: the installed xcframework matches the record, and the check refuses a
  library with one byte more, an extra file and a missing header. `build-iroh-ffi.sh`, plain and
  with `--update-record`, stops before its work directory with a message naming both versions
  when `xcodebuild` reports another Xcode, no Xcode, or the pinned Xcode with another clang
  (stand-in tools first on PATH); with the pinned Xcode selected, `--check-xcode` passes (skipped
  on a Mac without it). With a stand-in Xcode, Rust toolchain, work directory and `CARGO_HOME` at
  paths with spaces, a quote and a `$`, the script gives cargo each path flag whole in
  `CARGO_ENCODED_RUSTFLAGS` (`RUSTFLAGS` unset) and cc-rs `CFLAGS` that split, as a shell
  splits them (Python's `shlex`), into the same whole flags, with `CC_SHELL_ESCAPED_FLAGS=1`.
